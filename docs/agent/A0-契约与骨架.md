## 这个阶段只干一件事

把"数据长什么样"用代码钉死，逻辑一行不写。

顺序不能反的原因：主循环、工具、存档全都围着 `AgentState` 和 `Verdict` 转。schema 是全项目改动成本最高的东西——A4 的存档表主键、A5 的挂起恢复、A8 的评测对比，全都建立在字段不轻易变的前提上。现在多花一天想清楚字段，省掉后面三周的返工。

## verdict.py

```python
from __future__ import annotations
from typing import Literal
from pydantic import BaseModel, Field

# 五个值是和 Java 侧约定死的（docs/01 §三、docs/03 §5.6），一个都不能动。
# 【坑】不要"顺手"加 UNKNOWN / PENDING 之类的值。Java 侧的分流是 switch，
# 多出来的值会掉进 else，线上表现为"所有结果都进人工队列"——
# 两边都不报错，属于最难查的一类 bug。
VerdictType = Literal["PASS", "PARTIAL", "FAIL", "NOT_FOUND", "NEG_DEVIATION"]


class Evidence(BaseModel):
    doc: str                    # 文档名，前端展示"依据：xxx.docx"
    page: int                   # 页码。前端高亮和人工抽查都靠它
    section: str                # 章节号，如 "3.2.4"。来自分块时的 section_path
    text: str                   # 原文摘录。注意必须是原文的连续片段，A6 会校验
    bbox: list[float] | None = None   # 文内坐标。有它可以做点击高亮，没有就 None
    chunk_id: str               # 指回 chunks 表的主键
    # 【why】chunk_id 不是多余的。A6 校验证据真伪时，用它到"本次检索结果池"
    # 里反查原文；没有它，校验只能靠文本模糊匹配，编造的证据混进来的概率大增。


class EngineMeta(BaseModel):
    # 每条结论必须自带"当时用的什么模型/提示词/索引版本"。
    # 【why】出争议时的第一问题是"当时是哪个版本判的"。事后去日志里翻成本很高，
    # 直接写进结论里，审计和回放才成立。
    model: str
    prompt_version: str         # 改一次提示词 bump 一次，格式 v0.1 / v0.2
    index_version: str          # 对应 documents.embedding_ver，换嵌入/重切分时变


class Verdict(BaseModel):
    verdict: VerdictType
    # 字段名叫 confidence 不叫 score：【坑】"分数"在检索语境里已经被重排分数占用，
    # 两个 score 混在 trace 里查问题会看串。
    confidence: float = Field(ge=0, le=1)
    evidence: list[Evidence] = []
    reason: str                 # 给人看的判定理由，会进偏离表
    missing_aspects: list[str] = []   # 对照 requirement.must 缺了哪几条，PARTIAL 时必填
    needs_human: bool = False
    engine: EngineMeta
```

## state.py

```python
from __future__ import annotations
import time
from typing import Any, Literal
from pydantic import BaseModel


class BudgetState(BaseModel):
    used_steps: int = 0
    used_tokens: int = 0
    used_cost_cny: float = 0.0
    deadline_ts: float = 0.0          # time.monotonic() 的值，不是墙上时间
    # 【why】monotonic 而非 datetime.now()：墙上时间会被 NTP 校准往回拨，
    # 任务跑一半时间倒流，deadline 判断就乱了。monotonic 只进不退。

    def exceeded(self) -> bool:
        from agent.config import settings
        return (
            self.used_tokens >= settings.agent_max_tokens_per_item
            or self.used_cost_cny >= settings.agent_max_cost_per_item_cny
        )

    def deadline_passed(self) -> bool:
        # 【why】deadline 判断收编成契约方法：A2 循环直接调它，
        # 不让每个调用点自己写 time.monotonic() 比较——写法漂移一次，
        # "卡死不兜底"和"误杀正常任务"就会随机出现
        return self.deadline_ts > 0 and time.monotonic() > self.deadline_ts


class ToolRecord(BaseModel):
    step: int
    tool_name: str
    args_digest: str                  # 入参的 sha256 前 8 位
    # 【why】存摘要不存全参：防打转检测只需要"参数是否和上次相同"，
    # 全参可能包含一大段 query 文本，80 项跑下来白白多几十 MB。
    latency_ms: int
    result_summary: str               # 如 "5 hits, coverage 2/3"
    ok: bool
    error: str | None = None


class AgentState(BaseModel):
    # ── 身份 ──
    task_id: str
    item_id: str                      # 如 "S3.2.4"
    # 【why】评分项内容必须随状态走，不能只存 item_id：A1 的查询构造、
    # A6 的覆盖率计算都直接读这两个字段；崩溃恢复后重新加载评分项
    # 就多一次 IO 和一次"加载失败"的分支
    item_text: str = ""               # 评分项原文
    requirement_must: list[str] = []  # 原子要求清单

    # ── 进度 ──
    step: int = 0
    # 【why】step 必须是单调递增整数，不能用时间戳代替：
    # 1) max_steps 要比较大小；2) 存档表主键是 (task_id, item_id, step)；
    # 3) 排查"卡在第几步"需要可排序。
    status: Literal["running", "pending_human", "done", "failed"] = "running"
    state_version: int = 0            # 乐观锁版本号，每次 save 加一
    # 【why】乐观锁：两个 worker 同时恢复同一个评分项时，后写的版本号会落后，
    # UPDATE 时用 WHERE state_version = 旧值 就能撞出冲突，立刻报错而不是互相覆盖。

    # ── 推理轨迹 ──
    messages: list[dict] = []
    # 【坑】这里只允许存 role/content/tool_call 的 id 和参数，绝不允许塞
    # 原始 HTTP 响应（里面 usage / finish_reason 等几十个字段）。
    # 80 项 × 6 步全存原始响应，单任务的状态表几十 MB，
    # 恢复时读库比重新调一次 LLM 还慢。要存 usage 就聚合进 BudgetState。
    tool_records: list[ToolRecord] = []

    # ── 草稿纸 ──
    scratch: dict[str, Any] = {}
    # 【why】单独一个 scratch 而不是把中间结论塞进 messages：
    # 对话会越长越贵，scratch 是"人评审员的草稿纸"——看过哪些节、排除了哪些候选、
    # 缺口还剩什么。有了它，长对话可以压缩掉，只回传草稿纸，token 直接省一半。
    # 约定键名（写死，别让模型自由发挥）：
    #   seen_sections: list[str]    已展开读过的章节
    #   ruled_out: list[str]        已排除的候选及原因
    #   missing_aspects: list[str]  当前掌握的缺口

    # ── 预算 ──
    budget: BudgetState = BudgetState()

    # ── 检索会话池 ──
    session_hits: list[dict] = []
    # 【why】A6 证据回查的查证范围 = 本项执行中所有工具返回过的内容，
    # 必须落在 state 上而不是内存里：崩溃恢复（A4）/挂起恢复（A5）之后
    # 校验证据时，池子还得在。元素：{"chunk_id", "page", "section", "text"}
    # ——page 给 A1 算 Hit@5，chunk_id/text 给 A6 回查原文

    # ── 终态 ──
    verdict: Verdict | None = None
    terminated_by: Literal["answer", "max_steps", "timeout", "budget", "error"] | None = None
    # 【why】五个值缺一不可。没有它，线上出问题时无法回答
    # "这个评分项是判完了还是步数用完被硬停的"——这两种情况的可信度天差地别。
```

字段约束记住一条：**JSON 原生类型 + Pydantic 模型，别的都不要**。`datetime`、`Enum` 成员、DB 连接对象、httpx client，塞进 state 的那一刻就埋好了"恢复时序列化炸掉"的雷。

## decision.py：Decision 与 ToolSpec

```python
# decision.py —— 模型每一步输出什么
class Decision(BaseModel):
    action: Literal["tool", "final"]
    # 【why】先选动作再给内容：模型必须显式说"这步是调工具还是出结论"，
    # 程序就不用去自由文本里猜意图。猜错一次，整条链路的 parse 就崩。
    tool_name: str | None = None
    tool_args: dict | None = None
    scratch_patch: dict | None = None   # 本步对草稿纸的增量修改
    verdict: Verdict | None = None      # action=final 时必填

# 同文件的 ToolSpec —— 工具说明书（A3 的注册表按它登记四件套）
class ToolSpec(BaseModel):
    name: str
    description: str          # 这行字直接进 prompt，是模型决定调不调的唯一依据
    params: type[BaseModel]   # 入参用 Pydantic 定义，dispatch 层自动校验
    when_to_use: str
    when_not_to_use: str      # 【实测】这行对减少乱调的作用比 description 还大
    cost_hint: str            # 如 "1 次检索，约 200ms"。给模型成本意识
```

## 往返测试：A0 真正的验收

序列化最常见的故障不是"存不进去"，而是**"存得进、读不回"**——某字段是 `datetime` 或 `Enum`，dump 时被静默转成字符串，恢复时 `model_validate_json` 直接炸。等问题暴露在"线上崩溃恢复"时，已经晚了。所以 A0 的验收就是把它提前到今天：

```python
# tests/agent/test_contracts.py
import pytest
from agent.contracts.state import AgentState
from agent.contracts.verdict import EngineMeta, Verdict
from agent.contracts.fake_llm import make_fake_state

SAMPLES = [
    make_fake_state(),                      # helper 里造一个字段齐全的实例
    make_fake_state(status="pending_human"),
    make_fake_state(terminated_by="max_steps"),
]

@pytest.mark.parametrize("state", SAMPLES)
def test_state_json_roundtrip(state: AgentState):
    text = state.model_dump_json()
    again = AgentState.model_validate_json(text)
    # Pydantic 的 == 是逐字段比较，丢字段、类型漂移、默认值被改写都会在这里炸
    assert again == state

def test_verdict_rejects_unknown_type():
    # 【why】要测非法值进不来。如果 Literal 写漏了或者被人改成 str，
    # 这个测试第一个报警——比线上"Java 收到未知判定"早几个月
    with pytest.raises(ValueError):
        Verdict(verdict="MAYBE", confidence=0.5, reason="x",
                engine=EngineMeta(model="m", prompt_version="v0.1", index_version="idx"))
```

## fake_llm.py 与空闭环

```python
# ── 测试 helper：字段齐全的假状态 / 假结论 ──
# 【why】下面的往返测试要覆盖"终态、挂起中、被硬停"三种形态，
# 每个测试手搓一遍字段必然漏字段——helper 是字段清单的唯一来源，
# A0 改契约时只改这一处，所有测试自动跟上
def make_fake_state(task_id: str = "t1", item_id: str = "S3.2.4", **kw) -> AgentState:
    return AgentState(
        task_id=task_id, item_id=item_id,
        item_text="支持国产数据库（达梦、人大金仓）适配",
        requirement_must=["达梦适配", "人大金仓适配"],
        **kw,
    )

def make_fake_verdict(**kw) -> Verdict:
    base = dict(
        verdict="PARTIAL", confidence=0.8,
        evidence=[Evidence(doc="投标文件.docx", page=87, section="3.2.4",
                           text="已完成达梦DM8的适配测试", chunk_id="c-001")],
        reason="仅提及达梦，未提及人大金仓",
        missing_aspects=["人大金仓适配"],
        engine=EngineMeta(model="fake", prompt_version="v0.1",
                          index_version="idx-test"),
    )
    base.update(kw)
    return Verdict(**base)


class ScriptedFakeLLM:
    """按脚本逐个回放 Decision。不联网、不花钱、结果确定。"""
    def __init__(self, script: list[Decision]):
        self.script = script
        self.cursor = 0

    async def decide(self, messages, tools, schema) -> Decision:
        d = self.script[self.cursor]
        self.cursor += 1
        return d
        # 脚本用完还再调用 → 测试直接 IndexError 炸掉。
        # 这是故意的：说明循环没按预期终止，比静默返回 None 好查得多。
```

空闭环测试：脚本给三步——调 search → 出 final → 校验 state 终态：

## 本阶段术语

> 【白话】**Pydantic**：声明式数据校验库。字段和类型写清楚，它负责拦住不合规的输入、做 JSON 转换。本项目里它承担的是"契约执法者"的角色。
> 【白话】**Literal**：把取值范围锁死成几个字符串。比 `str` + if 判断强得多——拼错立刻报错，而不是静默通过。
> 【白话】**无损往返**：对象 → JSON → 对象，前后逐字段相等。存档系统能否正确恢复的前提。
> 【白话】**乐观锁**：写之前不加锁，写的时候核对版本号，对不上说明有人插手，报错重来。代价小，代价是偶尔要重试——本项目里恢复操作一天没几次，完全值。
