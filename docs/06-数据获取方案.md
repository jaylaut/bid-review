# 数据获取方案（Phase 0 前置）

> **回答的核心问题**：搭建 RAG 前，文档从哪里来？
> **关键现实**（2026-10 核实）：**招标文件（含评分办法、技术需求书）公开可免费下载；投标技术方案（实施方案/应答文件）属于商业秘密，法定不公开。**

---

## 一、先讲清楚现实：两类文档的可得性完全不同

| 文档类型 | 用途 | 可得性 | 依据 |
| --- | --- | --- | --- |
| **招标文件**（技术需求书 + 评分办法 + 合同条款） | 链路 A：评分项抽取；评估集题目来源 | ✅ **公开、免费、电子化下载** | 政府采购网/公共资源交易中心直接提供附件 |
| **投标技术方案**（应答文件/实施方案） | 链路 B：RAG 检索的"文档侧" | ❌ **法定不公开** | 投标文件属商业秘密（行政复议决定〔2026〕85号、重庆招投标条例答疑均明确）；佛山南海区案例公示部分应答时**明确排除"项目实施方案、售后服务方案"**——而这正是我们要的 |

**由此推出的策略**：数据是"**真实招标文件 + 领域专家自写投标方案**"的混合结构。这不是妥协，反而构成项目优势——真实评分项 + 完全可控的应答 ground truth。

---

## 二、招标文件获取渠道（真实公开，可直接操作）

| 渠道 | URL | 能拿到什么 | 操作方式 | 备注 |
| --- | --- | --- | --- | --- |
| **中国政府采购网** | ccgp.gov.cn（全国 + 省级分网入口） | 招标/采购公告、**采购文件附件**（zip/pdf/docx）、中标结果 | 搜索行业关键词 → 进公告页 → 下载附件 | 最主渠道；部分附件直接下载 |
| **各省公共资源交易中心** | 如重庆 cqggzy.com、四川、山东、广东等省级平台 | 招标文件、答疑补遗、中标候选人 | 交易大厅搜索 → 项目详情 → 附件 | 工程类项目为主，技术标方案要素齐全 |
| **中国招标投标公共服务平台** | cebpubservice.com | 招标公告、中标候选人公示 | 搜索 → 详情 | 汇聚多平台信息，可当索引 |
| 地方电子招投标平台 / 政采云 | 各地 zfcg 平台 | 采购文件 | 部分需注册/登录 | 视地区而异 |

**筛选技巧（决定数据质量）**：
- 关键词优先选**技术服务类项目**（信息系统建设、运维服务、咨询、系统集成、软件开发），技术评分项最丰富
- 优先选**综合评分法**且"技术分占比高"的项目（评分办法是链路 A 的富矿）
- 用 `评分办法 综合评分 技术方案` / `技术需求书` / `技术服务要求` 组合检索

**获取后登记**：每套文件记入 `data/sources.md`（来源 URL、项目编号、行业、下载日期、评分办法类型），溯源是评估集可信度的前提。

## 三、投标技术方案的三个获取方案（这是真正的难点）

### 方案一（推荐）：领域专家自写模拟投标方案

针对真实招标文件，自己撰写 3–5 份模拟投标技术方案。理由：

1. **你是领域专家**——16 年企业级交付经验，写出来的技术应答结构真实可信（不是"编造"，是"按真实写法写"）
2. **评估集 ground truth 完全可控**：每个评分项的应答位置、响应程度你都知道，标注零争议
3. **刻意制造难度梯度**：正常响应 / 部分响应 / 未响应 / 负偏离四类各造一批，评估集才有区分度
4. 规避商业秘密与隐私问题（模拟方案不冒用真实公司名）

### 方案二：公开技术文档替代"应答库"

用公开的技术方案类文档充当检索语料：厂商产品技术白皮书、解决方案 PDF、实施手册、项目验收报告、公开的技术标书模板。优点：数据真实公开、量可扩充；缺点：与"评分项一一对应"的应答关系弱化，偏离比对逻辑要调整。

### 方案三：个别公示项目（价值有限，仅作补充）

极少数地方（如佛山南海区政策）会公示中标人投标文件的**部分内容**（营业执照、资质、业绩、设备参数），但**明确排除实施方案/服务方案**——只能补充"资质/业绩"类评分项的素材，无法充当技术方案主料。

**结论**：主用方案一，方案二作语料扩充（尤其"历史范本库"场景），方案三仅当零星补充。

## 四、Phase 0 采集清单与数量目标

| 项 | 数量 | 用途 |
| --- | --- | --- |
| 招标文件（含评分办法） | **10–15 套**，覆盖 3–5 个行业 | 链路 A 抽取 + 评分项来源 |
| 自写模拟投标方案 | **3–5 份**（每份对应一套招标文件） | 链路 B 检索语料 |
| 评分项标注（golden set，标准答案集：每题标好"应判成什么、依据在哪页"） | **≥120 条**，四类判定分布 5:2:2:1 | 评估集 |

> 不追求数量，追求**标注质量**。10 套真实招标文件 + 3 份自写方案，足够支撑 12 周全流程；不够再扩。

## 五、合规边界（必须遵守）

1. **只用公开信息**，学习/个人项目用途；不爬取需登录或付费接口的付费内容
2. **反爬自律**：单线程、请求间隔 2–3s、尊重 robots.txt、不批量高频抓取（政府采购网是公共服务，别给它添堵）
3. **来源登记**：每个文件留 URL + 下载时间，可追溯
4. **模拟方案脱敏**：自写方案用虚构公司名/项目名，不冒用真实主体
5. 若未来商用，需重新评估数据授权与合规

## 六、采集脚本（已落地并验证）

> 完整可运行脚本：`scripts/fetch_tenders.py`。要点：**用 `curl_cffi` 模拟 Chrome TLS 指纹**（`impersonate='chrome124'`），已实测突破 ccgp 的 WAF（403 的根因是 TLS 指纹被拦，而非 IP 段）；**curl_cffi 模式下不能手动塞 header**（会污染浏览器指纹重新触发 403）。三模式 + `--check` 连通性自检，端到端下载已验证（真实招标文件 zip → PDF + docx）。

```python
# scripts/fetch_tenders.py —— 已可用，此处仅列关键设计
# · url 模式：读 data/tender_urls.txt 逐条解析附件下载（默认，最稳）
# · search 模式：调 search.ccgp.gov.cn 自动搜索（站点结构可能变，先 --dry-run 校准）
# · import 模式：浏览器手动下载后归档登记（反爬兜底）
# · --check：一条命令验证本机连通性 + 解析
# · 限速 2.5s + 随机抖动 / 403·429 指数退避 / 断点续传(.downloaded.json) / 来源登记(source.txt)
```

**目录结构**（配合脚本）：

```

                           #   01 §Phase0 / 02 §八 / 11 §P0.4 的权威路径都是 eval/golden_set.jsonl
```

## 七、诚实的一句话结论

**招标文件是公开的真实数据，投标方案必须是"专家自写的真实结构数据"。** 面试时要能主动讲清楚这个设计：真实评分项 + 可控应答 ground truth，让评估集"既真实又可判定"——这比硬凑一份来源存疑的投标方案更有说服力，也恰好绕开了商业秘密的合规风险。
