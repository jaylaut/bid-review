## 这个阶段只干一件事

把评分项变成一次"又快又全"的召回，且**权限在 SQL 层强制生效，业务代码绕不过去**。

## 先讲清楚：为什么不用 LLM 改写查询

通用 RAG 教程会教你 Multi-Query / HyDE / 查询改写。**本项目一概不用**，原因是查询性质不同（03 §一的判表）：

- 评分项文本本身就是**精确的检索意图**："支持国产数据库（达梦、人大金仓）适配"没有歧义、没有口语、没有指代；
- LLM 改写引入两个问题：**改写结果不稳定**（评测没法归因，同一题两次改写不同，Hit@5 数字全是噪声）、**多花 token**；
- 定向检索用确定性模板就对了。Multi-Query/HyDE 留给"评审专家自由追问"的交互场景——那是另一个入口，不在本链路。

## 查询构造：确定性模板

构造在 `agent/query.py`（Agent 侧），产出 `RetrieveQuery`（R0 契约）交给 `rag/online` 执行。**职责边界：rag 不依赖 agent，所以契约类型定义在 rag 侧，构造逻辑在 agent 侧**。

```python
def build_query(state: AgentState, embedding: list[float], acl: list[str]) -> RetrieveQuery:
    must = state.requirement_must
    # must 要点拼进查询文本："支持国产数据库适配"本身不带"金仓"，
    # 不拼的话写金仓的那段靠向量也能召回但排名吃亏
    query_text = f"{state.item_text}。要求要点：{'；'.join(must)}" if must else state.item_text

    # must 的名词短语 + 型号/标准号正则（DM8、ISO27001、SLA99.9）
    keywords = list(dict.fromkeys(          # 去重保序
        must + _CODE_RE.findall(state.item_text + " " + " ".join(must))
    ))
    return RetrieveQuery(item_id=..., query_text=query_text, keywords=keywords,
                         embedding=embedding, project_id=..., acl=acl)
```

三处设计的道理：

- **`query_text` 拼上 must 要点**：评分项原文可能只说"支持国产数据库适配"，而应答段落写的是"人大金仓 KingbaseES 适配测试"——不把"人大金仓适配"拼进查询，这段靠向量 latent 关联也许能召回，但排名吃亏。拼接是零成本的排名修正。
- **`keywords` 喂稀疏路**：向量对"达梦DM8"和"达梦 DM8"（有无空格）的区分远不如字面匹配。**型号类评分项漏检，九成是稀疏路没拿到关键词**。
- **型号/标准号正则**（`[A-Za-z]{2,}\d+(?:\.\d+)*` 等）：从评分项文本里抠 `DM8`、`ISO27001`、`99.9%` 这类字面锚点。专有名词密度高是标书查询的最大特征（03 §一），稀疏路必须喂饱。

## 双路并发召回

async def retrieve(q: RetrieveQuery, ctx: AuthContext, *, fetch=None, pool=POOL) -> list[Candidate]:

**并发 ≈ 慢的一路，不是两路之和**。两路各 60 候选，融合成 100 的池子交给 R5。

### 稠密路：HNSW 内积

```sql
-- 【坑·已修】原写法 "SET LOCAL ...; SELECT ..." 两条语句拼一个字符串——
-- asyncpg 参数化查询（extended protocol）不允许多语句，真库直接报错。
-- 修正：set_config(..., true) 放 CTE，is_local=true 等价 SET LOCAL，
-- 单语句保持 prepared statement 可用。
WITH _cfg AS (SELECT set_config('hnsw.ef_search', '128', true))
SELECT c.chunk_id, ..., -(c.embedding <#> $1::vector) AS score
FROM _cfg, chunks c
WHERE c.project_id = $2 AND c.acl @> $3::jsonb AND c.chunk_kind <> 'caption'
ORDER BY c.embedding <#> $1::vector
LIMIT $4
```

三个细节，每个都踩过或差一点踩：

1. **`SET LOCAL` 不能和多语句拼**：asyncpg 的 extended protocol 一条消息只能一条语句。`set_config('hnsw.ef_search', '128', true)` 放 CTE 是等价替代——`is_local=true` 就是 SET LOCAL 的语义，且保持 prepared statement 可缓存。
2. **`-(embedding <#> $1)` 取负**：`<#>` 是负内积（PG 约定距离越小越近），取负还原成"越大越像"的分数。向量已归一化（R3），内积 = 余弦。
3. **`chunk_kind <> 'caption'`**：图注太短没信息量，R2 已经决定 caption 不参与正文检索，这里兑现。

### 稀疏路：zhparser 全文

```sql
SELECT chunk_id, ..., ts_rank_cd(tsv, query, 32) AS score
FROM chunks, plainto_tsquery('zh', $1) query
WHERE c.project_id = $2 AND acl @> $3::jsonb AND tsv @@ query
ORDER BY score DESC LIMIT $4
```

- `plainto_tsquery('zh', ...)`：zhparser 中文分词后的查询，`plainto` 版本把用户输入当纯文本（不会把 `DM8` 里的特殊字符当语法）——评分项关键词拼接后有分号有括号，必须 plainto。
- `ts_rank_cd(..., 32)`：覆盖密度（cover density）排序函数，词挨得近的段落排得高，走的是 BM25 语义家族。
- **兜底**：`keywords` 为空时用 `query_text` 全文查——总比稀疏路空手回来好。

## 权限：三层防御，层层都不能少

这是企业 RAG 和 demo 的分水岭。绝大多数 demo 的死穴就是"检索不过滤"——本项目把权限做成三层，任何一层被绕过，另外两层还在：

```python
# 第一层：入参侧自检（retrieve 入口）
def _acl_guard(q: RetrieveQuery, ctx: AuthContext) -> None:
    if q.project_id != ctx.project_id:
        raise PermissionDenied(f"查询项目 {q.project_id} 与身份项目 {ctx.project_id} 不一致")

# 第二层：SQL 层强制注入（两条路都有）
WHERE c.project_id = $2 AND c.acl @> $3::jsonb

# 第三层：acl 序列化兜底
def _acl_json(q: RetrieveQuery) -> str:
    items = q.acl or [f"proj:{q.project_id}"]
    return json.dumps(items, ensure_ascii=False)
```

- **第一层为什么 raise 而不是返回空**：调用方构造查询时带错 `project_id`（比如把用户 A 的查询配了用户 B 的项目），**返回空结果会被上层当成"方案没写这条"——是错误结论，不是空页**。宁可炸一个 PermissionDenied，不要静默产出错误判定。
- **第二层是设计核心**：过滤条件由数据访问层按 `AuthContext` 注入，**业务代码想绕都绕不过去**——它根本接触不到不过滤的 SQL。权限前置到召回前，而不是召回后过滤（后者漏出去的数据已经在响应里了）。
- **第三层兜底空数组**：asyncpg 的 jsonb 参数吃字符串不吃 list；且**空 acl 数组 `@>` 一切为 False**——传 `[]` 进去，查询静默返回零结果，又是一个"看起来像没数据"的陷阱。空 acl 兜底 `proj:{project_id}` 标签，保证至少按项目隔离。

## 本阶段术语

> 【白话】**双路召回**：向量路（语义像）和全文路（字面准）同时查，各取 60 条。专有名词密集的场景，两路缺一个都会漏。
> 【白话】**ef_search**：HNSW 的查询时参数，越大越准越慢。128 是精度/延迟的平衡点，会话内动态可调、不用重启。
> 【白话】**BM25 / ts_rank_cd**：PG 全文检索的相关性排序，词频 + 覆盖密度。中文靠 zhparser 分词。
> 【白话】**plainto_tsquery**：把用户输入当纯文本的全文查询构造器。不会把 `DM8`、括号当查询语法——评测项文本必须用它。
> 【白话】**权限前置**：过滤条件在 SQL 层强制注入，召回之前就生效。事后过滤 = 数据已经泄露了。
